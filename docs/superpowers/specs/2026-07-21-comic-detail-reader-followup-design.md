# JoyComic 漫画详情与阅读器问题修复设计

日期：2026-07-21

状态：待用户审阅

实现者：Grok（Codex 负责规格、审查与验收）

## 1. 背景与目标

基于上一版详情页重构和用户提供的手机截图，修复详情页的几何层级、简介布局、JM 缩略图解扰、章节页缩略图、相关推荐安全距离与标题截断问题；同时为阅读器黑屏增加可导出的分阶段诊断证据。

本次不改变已确认的信息架构：手机详情页保留评分数字与星级、作者、分类/标签、收藏状态、章节数、浏览量、点赞量和评论数；最近章节横向展示最多 6 章；下载只出现在全部章节页；评论进入独立页面；不恢复评分人数、人气榜或固定底栏。

## 2. 已确认的根因

### 2.1 详情页几何

- `HeroHeader` 当前以固定的 `surfaceExtra` 和 `seamTop` 计算头部，封面结束后仍保留明显空白，导致统计区离封面过远。
- 标题带按自己的底部定位，没有以悬浮封面的底部作为对齐基线。
- 视觉目标是：内容表面从封面顶部约 2/3 处开始，封面底部约 1/3 保持悬浮在内容表面上。
- 骨架屏必须使用同一几何公式，否则加载态和成功态会跳动。

### 2.2 简介与相关推荐

- 简介按钮虽然设置了右侧定位，但直接覆盖在折叠文本上，没有为按钮保留右侧文本空间。
- 推荐卡复用海报卡的单行标题约束。
- 详情页末尾固定间距没有合并系统底部安全区，在有手势条或操作栏的手机上可能贴底。

### 2.3 JM 缩略图与章节页

- `DetailViewModel.loadChapterThumbnail` 返回原始第一页 URL。
- `ChapterThumbnail` 和章节网格使用 `CachedNetworkImage`，只接收 URL/headers，没有使用阅读器的 `getImageLoadingConfig`、备用图床和 `jmReaderTransformer`。
- 因此 JM 章节图虽然下载成功，仍以分片/乱码原图显示；详情最近章节与全部章节页共享此问题。

### 2.4 阅读器黑屏诊断缺口

- 阅读器已有加载失败、候选图床失败和日志导出能力，但日志缺少一次加载的关联 ID，以及配置解析、解扰转换、解码和首帧显示边界。
- 黑屏可能发生在章节 API、图片配置、下载、JM 解扰、Flutter codec、预加载或列表渲染任一层；必须记录每个边界的结果，不能只增加一句“加载失败”。

## 3. 方案与边界

采用约束驱动布局和统一图片管线：

1. 以封面尺寸和内容宽度计算头部 seam、标题带、封面底部和元数据起点；不靠额外固定空白修视觉。
2. 详情缩略图和阅读器共享同一套 source-aware image descriptor：URL、缓存键、headers、fallback URLs、可选 bytes transformer。JM 缩略图必须使用与阅读器相同的解扰函数。
3. 日志增加短生命周期 reader trace，不记录 token、Cookie、完整敏感请求头或可复用的认证 URL；保留现有日志页和导出能力。

不采用只改几个常量的方案，因为它无法保证平板、桌面和大字号下的几何一致性；不重写整个阅读器或下载管理器，只补充共享图片描述与诊断边界。

## 4. 详情页修复设计

### 4.1 头部几何

- 封面仍以 3:4 比例悬浮，宽度继续按手机/平板/桌面断点约束。
- 对每个布局宽度计算 `coverHeight`、`coverTop`、`coverBottom`。
- 内容表面 seam 位于封面顶部约 2/3 高度，即封面底部约 1/3 位于内容表面之上。
- 统计/元数据区紧跟封面底部，仅保留设计间距；不得再出现由 hero 总高度产生的无效空白。
- 标题、作者和标签的视觉底部与封面底部对齐；当标题过长或系统字号放大时，使用最大行数、可用高度和省略保证不覆盖顶部栏。
- 评分数字和星级位于封面底部以下的内容面内，若无评分则不预留空洞。
- `DetailLoadingSkeleton` 必须复用相同的几何常量或纯计算 helper。

### 4.2 简介

- 折叠态最多显示三行正文。
- 当正文超过三行时，按钮位于正文区域最右侧，正文需要预留按钮宽度，不能被按钮背景盖住。
- 展开态显示完整正文，按钮仍保持右对齐并可收起。
- 无简介时显示轻量“暂无简介”，不保留大块固定高度。

### 4.3 相关推荐与底部安全区

- 相关推荐卡标题至少两行，标题容器高度固定，超长标题只在第二行末尾省略。
- 推荐区下方使用 `MediaQuery.paddingOf(context).bottom` 加主题设计间距，确保全面屏手势区和底部系统操作栏不遮挡内容。
- 该安全区只作用于页面内容末尾，不新增固定底部操作栏。

## 5. 统一图片描述与 JM 解扰

### 5.1 描述契约

新增或提取一个详情可使用的图片描述，至少包含：

- `url`
- `cacheKey`
- `headers`
- `fallbackUrls`
- 可选 `bytesTransformer`

详情章节缩略图加载器应从 `ComicSource.getImageLoadingConfig` 生成该描述。现有 `getThumbnailLoadingConfig` 仅返回 headers 时，可以作为非 JM 回退，但不得覆盖完整的 source-aware 配置。

### 5.2 渲染路径

- `ChapterThumbnail` 和完整章节页的 `ChapterGrid` 使用共享的 reader image provider 或等价的 source-aware provider。
- JM 图片必须依据章节 ID、无扩展名文件名和现有 scramble ID 调用 `jmReaderTransformer`；GIF 按现有规则跳过解扰。
- 缩略图缓存键必须稳定地包含源、漫画/章节和原始图片标识，避免“乱码原图”缓存污染解扰后的图片。
- 非 JM 源继续使用普通网络图片加载，并保留 fallback、失败占位和重试能力。
- 最近章节和全部章节页必须通过同一组件渲染，避免两个页面各自维护一套解扰逻辑。

## 6. 阅读器诊断日志

### 6.1 Trace 范围

每次章节加载生成短 trace ID；日志包含 source、comic ID、chapter ID 和图片序号，但不包含认证信息。至少记录：

1. ReaderProvider 开始加载章节，当前阅读模式和初始图片数量。
2. 章节 API 成功/失败、返回 URL 数量和空数据原因。
3. 每张图片的配置解析结果：是否结构化配置、fallback 数量、是否启用 JM transformer、缓存键摘要。
4. 网络候选结果：host、HTTP 状态、content type、字节数和魔数；不得写入完整 URL 查询参数或 headers。
5. transformer 开始/成功/失败，转换前后字节数和图片魔数。
6. Flutter codec 解码成功/失败。
7. `ReaderImage` 首帧解析成功及图片尺寸；预加载失败也要带 trace、索引和 cache key 摘要。
8. ReaderProvider 最终成功、失败、重试和章节切换。

### 6.2 用户获取日志

- 保留现有“诊断日志”页的查看、复制和导出能力。
- 阅读器错误页或更多菜单增加“查看诊断日志”入口，直接打开现有日志页；如果当前导航上下文不允许跳转，至少保留可复制的 trace ID。
- 日志查看页导出的文本可直接发给开发者，且不暴露 token、Cookie、密码、完整 Authorization 或敏感查询参数。
- 黑屏不应继续只显示空黑色 canvas；加载/错误态应保留占位、错误摘要和重试入口。

## 7. 测试与验收

### 7.1 详情 UI

- 手机、平板、桌面断点下，内容表面 seam 位于封面顶部约 2/3，封面底部约 1/3 悬浮。
- 元数据紧跟封面底部，不存在无效大空白；标题区域底部与封面底部对齐。
- 1.3 倍字号的长标题不覆盖顶部栏、不溢出、不改变布局宽度。
- 简介折叠三行，展开按钮右对齐且不遮挡正文；展开/收起可操作。
- 推荐标题最多两行、两行容器高度稳定；详情内容末尾包含系统底部安全区加设计间距。

### 7.2 图片与章节页

- JM 章节缩略图和全部章节页使用 transformer，测试可断言生成了 JM 配置而非裸 URL。
- 解扰后的图片 provider 与阅读器使用同一 cache key/transformer；非 JM 仍可正常显示。
- 缩略图下载失败显示占位并可重试，不阻塞章节点击和章节页渲染。

### 7.3 阅读器诊断

- 章节加载成功、空章节、API 错误、网络候选失败、解扰失败、codec 失败和首帧成功各有可检索日志。
- 日志包含 trace ID 和图片索引，但不包含认证凭证或完整敏感 URL。
- 阅读器错误/更多入口可以打开日志页或提供 trace ID。

### 7.4 必跑检查

```text
flutter analyze --no-pub
flutter test --no-pub <新增及受影响的定向测试>
git diff --check
```

完整测试中的既有失败需单独记录，不得因为本次修改而扩大失败范围。

## 8. 实现边界

允许修改：详情页组件、详情 ViewModel、章节页/章节卡、共享图片 provider 或其最小抽象、阅读器诊断日志及对应测试。

不得：恢复评分人数/人气榜/固定底栏；引入新的漫画内容；把认证信息写入日志；修改无关页面；提交或推送未经验证的代码。
