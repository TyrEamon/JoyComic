# JoyComic 用户反馈 UI、源管理与阅读器回归修复设计

**日期：** 2026-07-17 
**状态：** 用户已批准方案 B 
**范围：** 登录与账号资料、源管理、详情页、分类页、阅读器、日志导出

## 约束

- 主代理直接实现，不调用子代理。
- 不新增或修改测试用例；只运行现有测试、静态分析和针对修复路径的实际验证。
- 代码定位优先使用 fast-context，再用 `rg` 和文件精读核实。
- 仅作为哔咔分类视觉与交互参考，保持 JoyComic 双源架构。

## 问题与根因

1. 已登录仍可进入登录页：我的页账号卡和设置账号行无条件路由到 `/login`。
2. JM 缺少头像、名字等资料：登录响应只提取 AVS，`username/uid/photo` 等公开资料被丢弃。
3. 我的页“源管理”跳登录：源启用管理与账号登录被合并成同一入口。
4. 详情顶部按钮错误：独立分享按钮与更多按钮同时显示。
5. 封面右侧文字底部对齐：`InfoOverlay` 使用 `CrossAxisAlignment.end`，且顶部 padding 只包封面。
6. 详情统计排版错误与评分重复：统计项使用纵向 Column，详情下方再次渲染评分。
7. 分类页为 cell/chip：已有哔咔分类封面数据未被 UI 使用。
8. 分类底部被 TabBar 遮挡：主框架 `extendBody: true`，分类列表未补 60px 导航栏与系统底部安全区。
9. 设置源管理混乱：源管理组实际渲染账号信息；测速入口只取首个账号源。
10. JM 与哔咔阅读器黑屏：共享加载链缺少异常收敛和可见状态；图片显示/预加载未携带源图片加载配置。
11. 日志导出点击无反馈：导出流程无忙碌态、无异常捕获、无空数据提示，分享调用缺少稳定的锚点与结果反馈。

## 设计

### 账号与源管理

新增独立 `SourceManagerPage`，列出所有内置源并持久化启用状态。切换后调用 `ComicSource.reload` 刷新运行时源。账号入口单独分组：未登录才进入登录页，已登录打开账号信息/退出登录面板。我的页“源管理”始终进入源选择页。

JM 登录解析并保留公开资料：用户名、UID、昵称、等级、头像文件名。业务层写入 `source.data['user']`，头像文件名在图床确定后转换为完整 URL；退出登录同时清理这些字段。

### 设置页

设置页拆分为：

- 漫画源：源管理与已启用数量。
- 账号：JM、哔咔登录状态；已登录不进入登录表单。
- 线路与域名：禁漫线路/图床/API 域名测速，以及哔咔接入域名分别独立入口。

### 详情页

顶部仅保留返回和更多按钮，分享移动到更多菜单。`InfoOverlay` 对整个封面+文字组统一加顶部安全间距，并让封面与右侧标题/作者/星级块垂直居中。统计项使用横向图标+文字，删除下方重复评分。

### 分类页

分类页改为 风格响应式图片网格：正方形图片卡片加下方名称。哔咔直接使用 API `thumb/cover`；JM 无封面项使用统一图片占位，但保持同一网格结构，不再使用 ListTile/ActionChip。列表底部 padding = 60px 主导航高度 + 系统 bottom inset + 常规间距。

### 阅读器

共享阅读链增加明确状态：loader 为空、请求抛异常、返回错误、空图片均进入错误页；加载状态显示文字；进入时先显示工具栏，成功后才允许按配置自动隐藏。

新增阅读图片请求配置对象，保存实际 URL、headers、cacheKey。ReaderProvider 根据 `ComicSource.getImageLoadingConfig` 解析 URL/headers；ReaderImage 与 ImagePreloadController 使用同一配置，JM 与哔咔都经过同一可验证通路。图片最终失败显示明确错误和重试入口。

### 日志导出

导出按钮始终提供反馈：空日志提示、导出中禁用、写文件/分享异常提示。生成 MIME 为 `text/plain` 的 `.txt`，分享时提供当前按钮/页面的 `sharePositionOrigin`，分享完成或取消后恢复状态并展示结果。
