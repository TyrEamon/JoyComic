# JoyComic 暖纸墨配色系统设计规格

- 日期：2026-07-15
- 状态：已在对话中批准，等待书面规格复核
- 设计方向：A「暖纸墨 · 珊瑚红」
- 技术栈：Flutter / Material 3

## 1. 背景

JoyComic 当前同时存在三套颜色来源：

1. `AppColors` 中的粉色到紫色品牌渐变；
2. 页面组件自行声明的橙、蓝、绿、紫、粉等字面量颜色；
3. 漫画详情页通过 `PaletteExtractor` 从封面提取并注入的动态颜色。

结果是明暗主题语义不统一、图标和按钮过度渐变、常规产品界面出现彩色光晕，且页面组件可以绕过 `ThemeData` 自行决定颜色。新设计用暖纸中性色、墨色层级和单一珊瑚红强调色重建颜色系统，保持漫画封面作为内容视觉主体，而不是让应用框架与封面争夺注意力。

## 2. 目标与非目标

### 2.1 目标

- 为亮色和暗色模式建立完整、对称、可访问的语义颜色系统。
- 全应用只使用一个品牌强调色，不再使用粉紫双主色。
- 删除图标、按钮、标签、账号卡片和常规界面的装饰性渐变及彩色光晕。
- 页面通过 `ColorScheme` 和主题扩展取色，不直接依赖具体十六进制颜色。
- 保留真正用于可读性或加载反馈的功能性渐变，并集中管理。
- 移除封面动态取色对按钮、文字、星级、标签、操作栏和阴影的控制。
- 修复关于页写死版本号的问题。
- 建立对比度、主题契约和旧设计回归测试。

### 2.2 非目标

- 不修改禁漫或哔咔协议、API、登录和解析逻辑。
- 不修改收藏、历史、下载、缓存和数据库业务行为。
- 不进行路由重构。
- 不在本次工作中引入完整国际化；固定中文 UI 文案不是数据硬编码问题。
- 不重做页面布局、字体体系或动效体系，除非现有实现与新颜色系统直接冲突。
- 不把所有尺寸字面量机械地抽成 token；仅治理重复且具有系统语义的样式。

## 3. 视觉原则

### 3.1 视觉论点

JoyComic 应呈现“暖纸承载内容、墨色建立层级、珊瑚红指示动作”的编辑阅读体验：温暖但不甜腻，克制但不冷漠，漫画封面负责色彩，应用框架负责清晰。

### 3.2 核心规则

- 一个品牌强调色：珊瑚红。
- 中性表面优先，颜色只表达操作、选中或状态。
- 图标统一使用单色 Material 图标，不使用图标渐变。
- 常规卡片不依赖彩色阴影建立层级。
- 选中态同时使用填充、文字或指示条，不能只依靠颜色差异。
- 正文对比度不低于 4.5:1；大文字、图标和关键边界不低于 3:1。
- 触摸目标最小 44×44 逻辑像素，相邻目标保留合理间距。

## 4. 颜色系统

### 4.1 核心颜色

| 语义 | 亮色模式 | 暗色模式 |
|---|---:|---:|
| pageBackground | `#F7F5F2` | `#111315` |
| surface | `#FFFFFF` | `#191C1F` |
| surfaceMuted | `#F0EDE8` | `#202428` |
| surfaceRaised | `#E9E5DF` | `#272C31` |
| onSurface | `#1D1E20` | `#F2F3F4` |
| onSurfaceVariant | `#62666B` | `#B7BDC3` |
| primary | `#B7463F` | `#F08A82` |
| onPrimary | `#FFFFFF` | `#3B0B08` |
| primaryContainer | `#F6DEDA` | `#32110E` |
| onPrimaryContainer | `#5A1713` | `#FFDAD6` |
| outline | `#C9C3BB` | `#60676E` |
| outlineVariant | `#E1DDD7` | `#2E3338` |

亮色主按钮的白字对主色对比度为 5.30:1；暗色主按钮的深色字对主色对比度为 7.00:1。

### 4.2 状态颜色

| 状态 | 亮色前景 | 亮色容器/按钮文字 | 暗色前景 | 暗色容器/按钮文字 |
|---|---:|---:|---:|---:|
| success | `#2F6B4F` | `#FFFFFF` | `#8BD3AB` | `#0F3322` |
| warning / rating | `#8A5A00` | `#FFFFFF` | `#F1C56D` | `#3A2900` |
| info | `#3F5F88` | `#FFFFFF` | `#AAC7F0` | `#17314D` |
| error | `#B3261E` | `#FFFFFF` | `#FFB4AB` | `#690005` |

这些组合的对比度均高于 5.9:1。评分星使用 warning/rating 语义，不再复用品牌粉色。

### 4.3 加载和遮罩颜色

- 亮色 shimmer：`#E8E3DD` → `#F7F4F0` → `#E8E3DD`。
- 暗色 shimmer：`#24282C` → `#30363B` → `#24282C`。
- 图片文字前景使用统一 `onImage` 高对比颜色。
- 图片和阅读器遮罩使用主题扩展中的 ARGB 颜色，不在页面中重复 `Colors.black54`、`Colors.white70` 等写法。

## 5. 主题架构

颜色来源必须形成单向链路：

```text
AppColors
  → ColorScheme + AppSemanticColors
    → ThemeData
      → AppThemeContext
        → 页面与公共组件
```

### 5.1 `AppColors`

- 是正式色板十六进制值的唯一来源。
- 提供亮、暗 `ColorScheme` 和构建主题扩展所需的静态 token。
- 删除 `brandPink`、`brandViolet`、`brandGradient`、`brandGradientVertical` 及紫色专属骨架色。
- 不直接承担页面组件 API。

### 5.2 `AppSemanticColors`

新增 `ThemeExtension<AppSemanticColors>`，至少包含：

- `success`、`warning`、`info`、`rating`；
- `onImage`、`imageScrimStrong`、`imageScrimSoft`；
- `readerScrim`、`readerControlForeground`；
- `shimmerBase`、`shimmerHighlight`；
- 需要超出标准 `ColorScheme` 的收藏或禁用语义。

扩展必须实现 `copyWith` 和 `lerp`，并分别注入亮暗 `ThemeData.extensions`。

### 5.3 `AppThemeContext`

- 继续作为组件访问主题的轻量入口。
- 所有 getter 必须从当前 `ThemeData` 或 `AppSemanticColors` 派生。
- 不返回固定暗色常量。
- 缺失主题扩展时使用显式断言或安全回退，不能静默返回旧粉紫颜色。

### 5.4 阴影

- 删除浅紫“上抬光晕”。
- 封面、弹窗和真正悬浮控件可以保留中性黑色层级阴影。
- 常规卡片优先使用表面差和描边，不使用彩色阴影。

## 6. 渐变政策

### 6.1 必须删除

- 品牌粉紫渐变及其横向、纵向变体。
- 首页入口的逐项彩色渐变和 glow。
- 登录按钮和源选择的装饰渐变。
- 排行、搜索、分类选中项的渐变胶囊。
- “我的”、关于页和账号卡片的粉紫渐变。
- 详情页 `palette.gradient`、彩色操作栏和封面取色阴影。
- 阅读设置方向预览的粉紫渐变。
- 仅为“更精致”而添加的评论、简介、普通卡片渐变。

### 6.2 允许保留

仅允许以下功能性渐变：

1. 漫画封面、章节图片和阅读器内容上为文字或控件提供对比度的黑色透明遮罩；
2. 中性灰 shimmer 加载效果。

允许项必须由主题资源提供颜色。普通页面不得自行声明品牌或彩色 `LinearGradient`。

## 7. 组件映射

### 7.1 首页和发现

- `home_tool_bar.dart` 删除 `gradientStart`、`gradientEnd` 字段和逐入口颜色；所有入口采用统一扁平图标容器。
- `featured_carousel.dart` 的加载失败占位改为中性表面；黑色图片可读性遮罩保留。
- 首页标题的品牌 `ShaderMask` 改为纯色文字或标准主色强调。
- 排行、搜索和分类选中项使用 `primaryContainer`、主色文字或指示条，不使用渐变。

### 7.2 登录、我的、关于和设置

- 登录主操作使用标准 `FilledButton`；源切换使用平面选中态。
- “我的”账号区域使用表面层级和主色头像容器，不使用粉紫背景或彩色光晕。
- 关于页 Logo 使用纯色主色容器。
- 源测速、WebDAV、下载和日志等级统一使用语义状态色。
- 阅读设置预览使用中性表面和方向图标。

### 7.3 详情页

- 封面颜色不能控制按钮、文字、评分、收藏、标签、操作栏和阴影。
- 主操作固定使用主题主色；收藏和状态使用语义色。
- 保留封面和章节图片上的黑色可读性遮罩。
- 简介折叠区用明确的展开按钮和表面分隔替代装饰渐变。
- `detail_view_model.dart` 不再为视觉控件异步准备动态调色板。
- 语义审计确认 `PaletteExtractor` 只服务详情页视觉，因此最终实现删除 `palette_extractor.dart`、`ComicPalette`、详情模型字段、组件参数和异步取色调用。`image` 与 `dio` 仍被其他功能使用，不因本次删除而移除。

### 7.4 阅读器

- 顶部、底部控制层保留功能性黑色透明遮罩。
- 白色控件前景通过 `readerControlForeground` 获取。
- 页码、菜单锁和 Toast 使用阅读器专用语义 token。
- 阅读器专用高对比方案不得扩散到普通页面。

### 7.5 公共组件

- `PillBadge` 从 `Gradient` 参数改为 `backgroundColor` / `foregroundColor` 或直接从主题获取语义色。
- 漫画来源标签保留来源文字，不再用写死的紫色和粉色作为唯一识别方式。
- `EmptyState`、弹窗和登录守卫从当前主题获取颜色。
- shimmer 只使用批准的中性加载渐变。

## 8. 硬编码治理

### 8.1 生产数据审计结论

语义搜索没有发现生产页面仍在使用假漫画、假分类、假收藏、假历史、假下载或假缓存数据。分类、收藏、历史、下载、缓存、账号、设置、评论、章节和详情均连接真实 API、数据库或运行状态。本次不重写这些业务逻辑。

### 8.2 必须修复

- `about_page.dart` 中写死的 `0.1.0` 和构建号 `1`。
- 页面中的品牌色、状态色、文字色和表面色字面量。
- 页面重复的黑白图片遮罩颜色。
- 日志、测速、下载等功能散落的 `redAccent`、`orangeAccent`、`AppColors.hotAccent`。

关于页使用 `package_info_plus` 的 `PackageInfo.fromPlatform()` 读取运行时包信息，并通过可注入 loader 或专用视图模型让组件测试不依赖真实平台通道。GitHub 地址等稳定产品元数据可以保留为集中常量。实施时选择与当前 Flutter/Dart 约束兼容的 `package_info_plus` 版本并更新锁文件。

### 8.3 合法常量

以下不属于本次需要消除的错误硬编码：

- 固定 UI 文案；
- 源标识和协议字段；
- API 路径；
- 数据库表名与迁移版本；
- 路由地址；
- Material 图标；
- 测试 Mock 与 fixture；
- Codemagic 构建变量；
- 一次性且具有明确布局含义的尺寸。

## 9. 测试策略

### 9.1 主题契约测试

- 检查亮暗 `ColorScheme.brightness`。
- 检查核心 token 精确等于批准的 A 方案。
- 检查 `AppSemanticColors` 已注入且亮暗值不同。
- 检查关键组件不绕过当前主题。

### 9.2 对比度测试

- 正文与表面组合不低于 4.5:1。
- 大文字、图标与关键边界不低于 3:1。
- 主按钮、状态按钮、标签和禁用状态分别覆盖。
- 对比度计算使用标准 sRGB 相对亮度公式。

### 9.3 源码回归约束

生产源码不得重新出现：

- `brandPink`；
- `brandViolet`；
- `brandGradient`；
- `gradientStart`；
- `gradientEnd`。

新增测试或审计脚本限制普通页面中的彩色 `LinearGradient`。只允许主题遮罩、图片可读性蒙版和 shimmer 使用渐变。

### 9.4 关键组件测试

至少覆盖：

- 首页工具栏；
- 登录页；
- 我的页面；
- 关于页及注入版本信息；
- 搜索和排行选中状态；
- 详情主操作区；
- 阅读器控制层；
- 亮暗主题切换后的颜色更新。

### 9.5 全量验证

```powershell
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
git diff --check
```

实现完成后再次运行 `fast_context_search` 检查主题调用链，再用精确搜索确认不存在遗漏的旧颜色和装饰性渐变。

## 10. 实施顺序与风险控制

1. 先添加失败的主题契约、对比度和源码约束测试。
2. 建立新色板、`ColorScheme` 和主题扩展。
3. 迁移公共组件，再迁移页面，避免每个页面临时创造兼容颜色。
4. 移除动态封面取色视觉链路。
5. 修复运行时版本信息。
6. 清理旧 token、未使用导入和依赖。
7. 执行全量静态分析和测试。

主要风险是一次性删除旧 token 会产生大量编译错误。实施时采用“先提供新语义 API，再分组迁移消费者，最后删除旧 API”的顺序，但任何中间兼容层不得进入最终提交。

## 11. 验收标准

- 亮暗模式分别呈现批准的暖纸墨和珊瑚红色板。
- 普通图标、按钮、标签和卡片不存在装饰性渐变或彩色光晕。
- 封面颜色不再改变详情页操作控件。
- 仅图片可读性遮罩和 shimmer 使用渐变。
- 页面不保存正式品牌或状态 Hex 值。
- 关于页版本来自运行时包信息。
- 已有真实业务数据链路保持不变。
- 新增对比度与回归测试通过。
- `dart format`、`flutter analyze`、`flutter test` 和 `git diff --check` 全部通过。

## 12. 已解决问题

- 配色方向：A「暖纸墨 · 珊瑚红」。
- 强调色数量：一个。
- 图标渐变：全部删除。
- 封面动态取色：语义审计确认只服务详情视觉，最终删除实现和全部调用链。
- 功能性渐变：只允许图片/阅读器可读性遮罩与中性 shimmer。
- 固定中文 UI 文案：本次保留，不扩大到国际化。
- 远端推送：不属于设计阶段；完成实现和验证后按用户指示处理。
